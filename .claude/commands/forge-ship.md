You are executing the Forge ship workflow. This is a state transition: brainstorming ends, a Jira ticket is created, and the session is cleared.

## Step 1 — Check for Previous Ship in This Session

If the current conversation already contains a "Ticket created:" line from a prior `/forge ship` run:

Output exactly:
```
Starting new session. Previous idea cleared.

No new ticket created — the previous IdeaReport was already shipped.
Run /forge <new idea> to begin the next brainstorming session.
```
Then stop.

## Step 2 — Locate Active IdeaReport

Search the current conversation for the most recent `## Forge IdeaReport` block.

If none found:
```
No active IdeaReport found.

Run /forge <idea> to start a brainstorming session, then return here when ready to ship.
```
Then stop.

If found, extract these fields exactly:
- **idea** — from the `**Idea:**` line
- **skill** — from the `**Skill:**` line
- **confidence_score** — the numeric value from `**Confidence:**` (integer only, no emoji)
- **confidence_emoji** — the emoji from the same line
- **round** — from `Round N` in the heading
- **effort_estimate** — from `**Effort estimate:**` line (S, M, L, or XL)
- **builder_extensions** — all bullet points under `**Extensions:**`
- **critic_weaknesses** — all bullet points under `**Weaknesses:**` (preserve `[resolvable]`/`[blocking]` labels)
- **open_questions** — all bullet points under `**Open questions**`

## Step 3 — Derive Story Points

Map effort estimate to story points:
- S → 1
- M → 3
- L → 5
- XL → 8
- Not found → 3 (default; note this in output with `[defaulted — no effort estimate in report]`)

## Step 4 — Build Acceptance Criteria

Construct a numbered list in this order:

1. From each `[blocking]` Critic weakness → `Must handle: {weakness rewritten as a positive requirement}`
2. From each `[resolvable]` Critic weakness → `Must handle: {weakness rewritten as a positive requirement}`
3. From each Builder extension → `Must include: {extension rewritten as a concrete deliverable}`
4. From each Open Question → `Must answer before release: {question}`

Rules for rewriting:
- Weaknesses: flip to requirement. "Auth service will be saturated under peak load" → "Must handle: auth token validation must be async and cached to avoid latency spikes under peak concurrent load"
- Extensions: make concrete. "Add observability hooks" → "Must include: structured log events for every auth step with correlation IDs"
- Keep each criterion to one sentence. No bullet points within criteria.

## Step 5 — Assemble Description

Assemble the full Jira description as plain text:

```
Generated by Forge — adversarial brainstorming for Claude Code
Skill: {skill} | Confidence: {score}/100 | Rounds: {N}

---

{full IdeaReport markdown block, verbatim from the conversation — include all rounds if multiple exist}

---

## Acceptance Criteria

{numbered list from Step 4, one item per line}
```

## Step 6 — Find Project and Create Ticket

### Step 6a — Discover available Jira projects

Call `getVisibleJiraProjects` (Atlassian MCP tool) with no arguments.

If the tool is unavailable or returns an error, output exactly:
```
Atlassian MCP not connected.

To enable /forge ship, add this to your .claude/settings.json:

{
  "mcpServers": {
    "atlassian": {
      "url": "https://mcp.atlassian.com/v1/mcp",
      "type": "http"
    }
  }
}

Reload Claude Code. On first use you will be prompted to authenticate via browser.
Your IdeaReport is still active — retry /forge ship once connected.
```
Then stop without clearing session state.

If projects are returned:
- **One project:** use it automatically.
- **Multiple projects:** pick the one most relevant to the idea context. If genuinely ambiguous, briefly list the options and ask the user which to use before proceeding.

From the selected project, note the `cloudId` (UUID) and `projectKey`.

### Step 6b — Create the ticket

Call `createJiraIssue` (Atlassian MCP tool):

| Field | Value |
|---|---|
| `cloudId` | from Step 6a |
| `projectKey` | from Step 6a |
| `issueTypeName` | `"Story"` |
| `summary` | idea trimmed to ≤ 100 characters |
| `description` | full assembled description from Step 5 |
| `additional_fields` | `{ "labels": ["forge", "{skill-name}"], "customfield_10016": {story_points} }` |

If the idea exceeds 100 characters: truncate at the last word boundary before 100 chars and append `...`.

## Step 7 — Handle Response

### On success:

Output exactly:
```
Ticket created: {TICKET-KEY} — {ticket URL}

Summary:    {summary}
Points:     {story_points} ({effort_estimate})
Labels:     forge, {skill-name}
Confidence: {score}/100 {emoji}

Acceptance criteria ({N} items):
{numbered list}

---
Starting new session. Previous idea cleared.
Run /forge <new idea> to start the next brainstorming session.
```

### On failure:

Output exactly:
```
Failed to create ticket: {error message from MCP tool}

Your IdeaReport is still active — the session has NOT been cleared.
Fix the issue and retry /forge ship.

Common causes:
  • Atlassian MCP not connected    → add mcpServers.atlassian to .claude/settings.json and reload
  • Not authenticated              → reload Claude Code to trigger the browser auth flow
  • Project not found              → verify the project exists and your account has access
  • "Story" type unavailable       → your Jira project must be a Software project (Scrum or Kanban)
```

Do NOT clear session state on failure. The IdeaReport must remain available for retry.
